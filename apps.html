Apps & documents

Everything is a document. Every document has a home.

The agent doesn’t answer next to your work — it works in it. Pages, boards, sheets, canvas, handwriting, audio: each is a document of some kind, each kind has an editor, and the apps on top are just folders that know how to show them. Agents create, fill and reshape all of it with the same tools you use.

Cortex

Chat, document and execute on one surface.

Cortex is where most work happens: a file tree on the left, the open document in the middle, the agent on the right — and a run panel when a document can execute. Whatever kind you open, Cortex picks the right editor.

  • Quick-open with ⌘O / ⌘P across the whole project.
  • Discussions tab: the inbox threads about the open document, right next to it.
  • PDF export with report themes — one CSS layer per customer or purpose.
  • Translate a selection, play audio and video in the preview, open encrypted documents locally.

Apps

Fifteen apps, one data model.

An app is a folder with a manifest. Its pages are ordinary documents — so the agent can read and write them, you can link to a place inside them, and they show up in search, WebDAV and exports like everything else.

New in 0.5

Handwriting, questionnaires, design.

Three new ways to put things into Vancetope — and for the agent to put things back.

kind: scribble

Scribble

Vector strokes on A4 sheets, pen or finger. Print it, OCR it, export a PDF. A vision model gets a clean image of the sheet, and drawing tools let the agent annotate it.

 kind: questions

Questionnaires

Several questions in one document, answered through a wizard in the web chat or line by line in the terminal. When an agent needs your input, it asks with one of these.

 app: designer

Designer

A design is a folder of HTML, CSS and assets. The preview runs in an opaque-origin sandbox, so a design can look like anything without being able to touch anything.

Document kinds

Thirty-odd kinds, one API.

A kind says what a document is — and so which editor opens it and what the agent can do with it. They all share the same read/write/version/lock surface, so a new kind is a new editor, not a new storage system.

workpage markdown sheet canvas mindmap diagram chart slides timeline map graph tree list records checklist calendar finance-tree scribble questions qrcode data formula tex compose age application app-view vance-recipe vance-workflow vance-scheduler vance-guard vance-hook vance-wizard vance-model vance-research-source vance-chat-theme

The vance-* kinds are the system’s own configuration — recipes, workflows, schedules, guards, models. They get form views and templates like any other document, which is why an agent can set up an automation by writing one.

Bistromath

Apps the agent builds for you.

Need a little tool nobody ships — a tracker, a calculator, a dashboard over your own documents? Ask for it. The app-builder recipe writes an app view: a document with a main.js that runs sandboxed in a null-origin iframe and talks to your data only through a narrow API.

  • Five bundled libraries — core, api, db, fmt, ui — so apps stay small.
  • Governance: apps are forbidden by default; each one asks for approval through your inbox.
  • Just a document: versioned, shareable, changeable by the next prompt.

# view.yaml — the widget names a state key
  - type: table

// main.js — runs in a null-origin sandbox
async function onAppInit() {
  const files = await vance.documents.list('invoices/')
  const rows = []
  for (const f of files)
    rows.push(await vance.documents.read(f.path))
  vance.state.set('invoices', rows)
}

Images, audio, scripts

Beyond text.

The agent can make and change the things that go into a document, not only the words around them.

fenchurch

Images

Generate pictures from a description with a style cascade per project — and now edit an existing image, image-to-image.

 hotblack

Audio new

Text-to-speech, transcription, music, audio analysis — plus local trim, mix, concat and convert via ffmpeg.

 compose

Runnable pages

Shell, Python, JavaScript, R, LaTeX or an LLM call — one block in a page, executed server-side, the result lands back in the page.

Working together

People and agents in the same document.

Collaboration isn’t a feature bolted on — it’s how every document works, whoever is typing.

live

Presence & merge

See who is in a document, get changes pushed live, and let a three-way merge resolve concurrent edits.

 history

Versions & locks

Every change is archived. A soft lock keeps the AI, people or kits out of a document you want left alone.

 inbox

Inbox & threads

An inbox item is one concern with at most one decision. Agents ask there, you answer there, and the thread stays next to the document.

 share

Sharing

Share a document into someone’s inbox, by mail or into a place in an app — sharing passes content, never permissions.

 sessions

Shared sessions

Several people in one chat with the agent — mentions decide who is being addressed.

 webdav

Finder & Obsidian

Mount a project over WebDAV and edit its documents with the tools you already have.
