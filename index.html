Why it exists

AI had no application.

Someone once told me AI chats have no application — you open ChatGPT and there’s just a text box; what are you supposed to do with it? It stuck with me. Vancetope is my answer: give AI a place — somewhere it lives, right next to your data — and with a place it finally has an application, something real to do.

What makes it tick

A few ideas do most of the work.

Everything else is a consequence of these.

01

Everything is a document

Recipes, prompts, skills, schedulers, hooks, guards, settings, even apps — all documents. A new automation is a new document. The system reshapes itself from its own data, and so can agents.

02

Agents drive (almost) everything

Nearly every capability is a tool: write documents, spawn workers, set triggers, research, delegate. You give the direction and step in whenever you want — the flow stays visible.

03

Code drives the flow

Engines are Java algorithms with a lifecycle — the code decides when the model is called and when work is done. Few engines, many recipes. That’s what lets an assignment run for days without drifting.

04

Built to work in, together

Cortex unites chat, documents and execute on one surface — live-edited with other people and with agents in the same session. Presence, merge, versioning and discussions included.

05

Projects draw the boundaries

A project is a bounded area with its own documents, config and agents. Settings, memory and permissions inherit down a scope cascade — tenant, project, user, session.

06

It runs itself

Schedulers, lifecycle hooks and webhooks fire recipes, scripts or workflows. Persistent agents keep a journal, wake on their own schedule — and pause to ask instead of guessing.

Work and life

One place for whatever you’re working on.

Work or personal — Vancetope holds both, kept apart in separate tenants. A five-minute question or a project that runs for weeks; something off the web, a document to reshape, files right there on your machine. It’s open-ended on purpose: the stuff you’d otherwise scatter across a dozen apps tends to just fit here.

Project kits

Start a project ready to work.

A kit is a git bundle of skills, recipes, tools and settings. Install one and a project arrives preconfigured — thinking patterns, worker recipes, tool packs, defaults. And kits inherit, so they compose:

basic → code-development → security
research writing learning communication finance-thinking legal-thinking mail-assistant + build your own

The interesting part isn’t the bundled ones — it’s that a kit is just a git repo. Point a project at yours and it’s productive from the first message.

The proof is the product

Written by agents. On purpose.

Every line of Vancetope is AI-written — directed, reviewed and shaped by one human. That’s not a confession, it’s the whole point: Vancetope is what working with agents over months actually builds — a large, coherent system you can run, read and change. The tool and the demo are the same thing.

Questions

Asked often enough to answer here.

Is Vancetope a product I can buy?

No. It’s a personal project with public source — no sales, no support contract, no hosted service. You run it yourself, on a laptop, a server or a cluster.

Which AI model does it use?

Yours. Vancetope ships no model: connect a hosted API or a local one — any OpenAI-compatible endpoint works. Which models hold up under agentic load is measured in the benchmarks.

What do I need to run it?

A machine with Docker. Two commands install the stack and set up your first tenant and user — a few minutes. Get started.

Does it send my data anywhere?

Only to the model endpoint you configured, and only what the agent sends it. No telemetry, no licence check, no account with us. Documents can be encrypted so that even your own server can’t read them. Security & self-hosting.

Is it open source?

Source-available: Business Source License 1.1, which turns into AGPLv3 on 2029-06-23. You can read, run and change it; the licence text on GitHub has the details.

Can my own coding agent work with it?

Yes. Vancetope is an MCP server with three doors — tenant, project and agents — behind OAuth 2.1, so Claude Code, Cursor and others connect with a browser login. MCP doors.

Honest bit

It’s a personal project.

I built Vancetope to develop LLM agents and shape them until I could actually work productively with them. Over time everything I found interesting went in — plus a few things I think others might get something out of.

No support contract and no roadmap promises — it’s a project, not a product. The source is public: read it, run it, take it for a spin. It’s source-available rather than classic open source, and where it goes from here I’m keeping open.

— Mike Hummel
