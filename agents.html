Agents & engines

Agents that work for days, not just for a turn.

A chat answers. Vancetope works: it breaks an assignment down, spawns workers, waits, checks, asks when it has to and carries on when you’re gone. The trick is that the model doesn’t drive the flow — an engine does, and the engine is code.

Engines

A handful of engines, many recipes.

An engine is a Java algorithm with a lifecycle: it decides when the model is called, which tools it gets and when the work is done. A recipe picks an engine and configures it — prompt, tools, model, skills. You spawn work by recipe name; a new kind of assignment is a new recipe, not new code.

Bulk & decisions · new in 0.5

Thousands of records, one steady run.

Wowbagger is for the work no chat can hold: classify every ticket, extract fields from every contract, rate every lead. A Ford agent steers; a mechanical worker pool does the records. Each published chunk is a commit, so a run survives a pod switch and resumes where it stopped.

  • Preflight with wowbagger_check before a single token is spent.
  • Wakeups for progress, failure cooldown and heartbeat — the agent looks in, not over every record.
  • Pluggable workers: a light LLM call, a script, or a Zem decision — each behind a model gate.
  • A cost report at the end of every run.

Zem brings decision models — System One for agents. A typed question goes in (yes/no, one of N, a score), a calibrated probability comes out: fast, cheap, no prose. The bundled command-safety recipe asks “is this shell command dangerous?” before it runs.

Persistent agents

An agent with a home, a journal and a schedule.

Trillian isn’t a session you open — it’s an agent that lives in Vancetope. It has its own identity and hub, wakes on its own schedule, keeps a journal and reflects on it. When it needs you, it parks the question in your inbox and waits instead of guessing.

identity

Its own account

A headless service account, a home project, a model gate — the agent works with exactly the rights you gave it.

 natures

Natures

A nature decides what a wakeup is worth. Several conversation heads let one agent hold many conversations at once.

 exposure

A door for other agents

Claude Code, Cursor or another Vancetope can talk to a Trillian over the agents MCP — gated, long-polled, closed when idle.

Your models

Bring your own model. Any of them.

Vancetope ships no model and sells no tokens. Point it at a hosted API or a model on your own machine — any OpenAI-compatible endpoint works — and give each job the model it deserves.

  • Aliases like default:chat or a fast tier, resolved per tenant, project or recipe.
  • Model discovery with endpoint pricing, and quotas from global down to user.
  • Small models welcome: Benjy and Wowbagger are built so that a local model can carry real work.
